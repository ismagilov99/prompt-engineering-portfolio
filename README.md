
# Prompt Engineering Portfolio

Профессиональная коллекция многоразовых, модельно-независимых систем для проектирования, генерации и аудита промтов.

## Обзор

Этот репозиторий содержит три взаимосвязанных фреймворка Prompt Engineering, предназначенных для разработки, генерации, проверки и итерационного улучшения сложных промтов для больших языковых моделей (LLM).

Системы построены вокруг единого подхода:

- шкала сложности задач от 1 до 5;
- адаптация под приоритеты задачи;
- явное управление требованиями и ограничениями;
- структурированное формирование промта;
- встроенные механизмы самопроверки;
- чек-листы контроля требований;
- работа с неоднозначностью и недостающими данными;
- итерационное улучшение;
- возможность адаптации под известную LLM или среду выполнения.

Фреймворки спроектированы как **model-agnostic**: они не требуют привязки к конкретному поставщику LLM, модели или API. При необходимости известные характеристики целевой среды могут использоваться как дополнительный слой адаптации.

## Prompt Systems

### 00 — Автоматический конструктор промтов

**Файл:** `00-automatic-prompt-architect.md`

Универсальная система построения промтов, которая анализирует задачу пользователя, определяет необходимый уровень сложности, специализацию, приоритет и требования к результату, а затем формирует готовый к использованию промт.

Поддерживает два режима работы:

- **Автоматический режим** — пользователь описывает задачу, после чего система самостоятельно анализирует необходимые параметры и предлагает их для подтверждения.
- **Интерактивный режим** — система последовательно задаёт вопросы, собирает необходимые параметры и затем формирует итоговый промт.

**Основные возможности:**

- пятиуровневая шкала сложности;
- специализированные режимы работы;
- динамическая специализация для нестандартных задач;
- адаптация под приоритеты;
- автоматическое выявление недостающих данных;
- явные запросы уточнений;
- работа с предположениями;
- чек-листы требований;
- дополнительные команды для анализа и сравнения;
- мульти-приоритетная генерация;
- мульти-модельная адаптация;
- мини-аудит;
- итерационное улучшение;
- структурированное формирование готового промта.

[Открыть Automatic Prompt Architect](00-automatic-prompt-architect.md)

### 02 — Генератор промтов

**Файл:** `02-prompt-generator.md`

Система генерации готовых к использованию промтов на основе явно заданных параметров задачи.

В отличие от автоматического конструктора, данный фреймворк ориентирован на более детерминированную генерацию: уровень, приоритет, требования и чек-лист задаются явно и используются как входные параметры.

**Основные возможности:**

- структурированная декомпозиция задачи;
- управление уровнем сложности;
- управление приоритетами;
- формирование роли и цели;
- формирование контекста и ограничений;
- определение формата результата;
- контроль требований через чек-лист;
- оценка предполагаемого объёма ответа;
- структурированное разбиение больших задач;
- внутренняя проверка перед выдачей результата;
- анализ рисков;
- адаптация под известную LLM или среду;
- мульти-приоритетная генерация;
- мульти-модельная генерация;
- итерационное улучшение.

[Открыть Prompt Generator](02-prompt-generator.md)

### 04 — Инспектор промтов

**Файл:** `04-prompt-inspector.md`

Система экспертного аудита и улучшения существующих промтов.

Inspector проверяет промт относительно заявленного уровня, приоритета, структуры и набора требований, выявляет слабые места и формирует точечные исправления.

**Основные возможности:**

- проверка соответствия заявленному уровню;
- анализ покрытия требований;
- проверка структуры промта;
- анализ конкретности и измеримости;
- выявление неоднозначностей;
- проверка обработки ограничений;
- проверка чек-листов;
- анализ соответствия приоритету;
- количественная оценка качества;
- фиксация конкретного исходного фрагмента проблемы;
- предложение точечного исправления;
- генерация полной исправленной версии;
- сравнение версий;
- проверка совместимости;
- симуляция результата;
- итерационное улучшение промта;
- профессиональные и безопасные ограничения.

## Принципы проектирования

### 1. Явные требования вместо скрытых предположений

Ключевые параметры задачи должны быть явно определены.

Если информации недостаточно, система должна запросить уточнения или явно обозначить используемые предположения.

### 2. Масштабируемая сложность

Каждый следующий уровень добавляет новые требования к предыдущему, позволяя использовать одну систему для задач разного масштаба.

### 3. Приоритеты изменяют акценты, а не смысл задачи

Выбранный приоритет влияет на архитектуру, глубину и методы решения, но не должен произвольно изменять исходную цель пользователя.

### 4. Проверяемость

Сложные промты должны иметь измеримые критерии качества, чек-листы или другие механизмы проверки результата.

### 5. Model-Agnostic по умолчанию

Основная логика не зависит от конкретной модели.

Если характеристики целевой LLM или среды известны и действительно важны для задачи, они могут использоваться для дополнительной адаптации.

### 6. Итеративное улучшение

Промт рассматривается не как статичный текст, а как артефакт, который можно анализировать, проверять, исправлять и сравнивать с предыдущими версиями.

### 7. Безопасность по умолчанию

Система должна работать в рамках законных, профессиональных и безопасных способов решения задач.
